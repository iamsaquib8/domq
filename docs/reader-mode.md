# Reader mode: agreement with Readability

How closely `Dom::main_content()` (`domq --main`, the `main` option of the MCP
tools) and `Dom::metadata()` agree with
[Mozilla Readability](https://github.com/mozilla/readability) (Firefox's
reader view) on Readability's 130 test pages at commit
[`ab4027a`](https://github.com/mozilla/readability/tree/ab4027a8b37669745016869a37a504727992b2ba/test/test-pages).
The reference is Readability's own output, so these numbers measure
**agreement**, not quality, and are not comparable with other extractors'
benchmark scores. For quality against human labels, see
[reader-quality.md](reader-quality.md) (the AEB and WCXB benchmarks).

what domq kept is article; **recall**: how much of the article domq kept.

## Metadata

`Dom::metadata()` against Readability's metadata, on the pages where
Readability found a value; equal after collapsing whitespace.

| Field | Pages | Same |
|---|---:|---:|
| title | 127 | 59.1% |
| author (byline) | 76 | 52.6% |
| site name | 62 | 85.5% |
| language | 73 | 100.0% |
| published time | 33 | 97.0% |

`Metadata::json_ld` holds the page's JSON-LD blocks for a JSON parser: on 25 pages, 34 blocks, of which 33 parse with `serde_json` as returned.

domq reads the title, author and published time from the page's JSON-LD
article first (`headline`, `author`, `datePublished`), then from meta tags and
other markup. Readability's byline also comes from the page text ("By Jane
Doe"), and its title drops a trailing site name ("Article | Site"); domq
reads both from markup only, so those two rows count differences of convention
too.
