**Breaking for JavaScript: the extraction API moved to `domq-wasm/extract`.** The `domq-wasm` root entry is now the core only (parse, `select`, `selectFirst`, `toText`, `toMarkdown`, `toHtml`, `errors`, `decode`, `resolveUrl`, `resolveSrcset` and `Document`), and `mainContent`, `metadata`, `links`, `resources`, `toMarkdownChunks`, `tables` and `toCsv` (the free functions and the `Document` methods) are no longer exported from it. If you used any of them in 0.6, change `import { mainContent } from "domq-wasm"` to `import { mainContent } from "domq-wasm/extract"`; `domq-wasm/extract` also exports everything in the core, so you can import all of it from there. Without the change the import fails (`mainContent` is not exported). The functions and their results are the same in both entries. Why: the single module grew from ~43 KB to ~78 KB gzipped as extraction landed ([#111](https://github.com/iamsaquib8/domq/issues/111)), so an app that only selects and converts paid for code it never ran. The npm package now holds two builds of one crate: the core is 56,647 bytes gzipped and `domq-wasm/extract` is 77,769 (0.6 shipped one module of ~65 KB; `main` before the split was 77,762). CI gates them at 60,000 and 80,000 bytes. The old 45 KiB goal is not met (the core is 55.3 KiB); see the ROADMAP's Budgets.
